monitoring script is to be run on the ubuntu server which will be the target machine
chmod +x monitor.sh
sudo ./monitor.sh

to compile .cpp code to machine binary 
g++ -O3 -pthread flood_engine.cpp -o flood_engine

to run tcp syn flood -- targetting handshake queue
sudo ./flood_engine 192.168.122.8 8080 8 tcp
if the attack is tcp syn flood, then syn packets are spammed from random fake ip addresses
and the server HAS to respond to all of them
THE MAIN SYMPTOM IS high Semi-Open (SYN-RECV) 
KERNEL DEFENSE IS SYN Cookies (intercepts queue floods)

to run udp flood -- targetting network bandwidth
sudo ./flood_engine 192.168.122.8 8080 8 udp
if the attack is upd flood, then a lot of fire and forget, handshakeless messages
are fired. 
so since no handshake the server cant just drop the packets... every packet is pulled
from the nic to dest port 
so we fire large blocks of random data 
THE MAIN SYMPTOM IS High Interface Dropped
KERNEL DEFENSE IS Packet Dropping (discards buffer overflows)

to run icmp flood -- targetting cpu core
sudo ./flood_engine 192.168.122.8 8080 8 icmp
if the attack is icmp flood, then each icmp ping req is treated as a 
software interrupt.
so for each req the server MUST reply to it 
hence, say 9 lakh packets come together then a hardware interrupt is triggered and
CPU immediately freezes 
THE MAIN SYMPTOM IS High CPU Software IRQ Load
KERNEL DEFENSE IS ICMP Rate Limiting (Ignores excess pings)
